## 5. 当前 V3 代码审计

当前 V3 分支已包含数学构造、P0/P1入口、225组参数筛选和 S-AB 离线检测代码。P0 与 P1 的历史报告已经提交：input_audit.md 和 mathematical_audit.md。P1 报告验证了30轮真实张量，使用 λ_A=5、λ_B=5，记录的基线保持、D 双路径、A/B 联合恢复、BA 相对误差和服务器 FedAvg 误差均通过。该报告可以作为数学实现的历史回归证据。以下项目仍需要在正式训练前修正。

### 5.1 数学构造

task2_core_v3.py 的全局因子基线保持公式成立：

\[
A_{AB}=A_U,\qquad B_{AB}=B_U
\]

独立 lambda_A、lambda_B 的设计可以保留。

需要增加低秩迹公式与显式 BA 的真实张量对照测试，并分别验证 A 因子变化、B 因子变化和有效 BA 更新。

### 5.2 固定增量回放

当前 task2_core_v3_p345.py 的 run_delta_replay 在 S-A、S-B 两条不同全局轨迹之间混合目标和背景更新，并把不同全局起点构造的 A、B 组合后与 U 比较。

不同分支的全局模型已经经过不同聚合过程。跨分支组合无法构成同一全局起点下的四分支反事实。

因此，固定增量回放不得用于正式参数筛选或阶段验收。V3 使用同一轮、同一全局起点的00/10/01/11真实聚合预检，并使用 S-A、S-B 独立多轮训练检查持续行为。

### 5.3 P0 输入审计

当前 scripts/e11_v3_p0_audit.py 的实际检查范围为：U、旧 S-A、旧 S-B 三条轨迹逐轮检查30轮文件数量、客户端键集合、张量有限性、global SHA 与 manifest 对应关系；N_dolly_s17_a5 只记录30轮上传数量和初始化哈希，没有逐轮检查全部上传与全局文件。

当前 P0 脚本还存在以下审计缺口：

1. 记录 git_head 和 remote_head，但 passed 条件没有要求两者相等。
2. 计算普通数据文件 SHA16，但没有与冻结 manifest 中的预期哈希逐项比较。
3. 没有对 N_dolly_s42_a5、N_dolly_s2026_a5 执行逐轮深度核验。
4. 旧 S-A/S-B 被列为 P0 必须完整的轨迹，但 V3 新设计不复用其上传和状态。
5. 没有对 U 全部30轮逐轮执行服务器 FedAvg 复算。

V3 P0 应改为深度核验 N_dolly_s17_a5 校准轨迹、N_dolly_s42_a5 独立检验轨迹、冻结数据和 U 历史输入；如果 N_dolly_s42_a5 缺失或不符合配置，则自动训练 N_v3_dolly_s42_a5。N_dolly_s2026_a5 作为可选重复验证。旧 S-A/S-B 只登记历史状态，不作为新实验的必要输入。必须检查本地 HEAD 与远程 HEAD 完全一致。现有 input_audit.md 中“U失败后不重训”的决定属于当时的离线诊断执行范围；V3 正式方案已定义新的90组题对和 U_v3 训练协议，该历史决定不限制新协议。

### 5.4 参数筛选实现

当前 run_lambda_screen 使用有效更新范数和合并后的 A/B 因子变化范数计算 J。合并指标可能掩盖 A、B 两个因子各自的变化失衡。V3 正式筛选必须分别计算 A 因子变化范数和 B 因子变化范数，并分别与九个正常客户端的中位数比较。检测阈值使用 N_dolly_s17_a5 校准，并使用 N_dolly_s42_a5 或自动训练的 N_v3_dolly_s42_a5 独立检验。

### 5.5 数学测试范围

已提交的 mathematical_audit.md 对30轮真实张量使用 λ_A=5、λ_B=5，五项核心等式全部通过。该报告属于当前 V3 代码和旧 U 轨迹的历史数学证据；新90组题对协议会生成新的 U 上传，因此必须在新 U 完成后重新执行全轮数学审计。公式推导表明联合恢复与 lambda 数值无关，但正式代码仍需对多个合法 lambda 组合执行真实张量回归，并补充低秩迹公式与显式 BA 乘积的独立对照测试。现有 pytest 中的 fake_pairs、fake_round 使用随机替代张量，不能作为真实训练数据或真实张量验收证据；V3 正式测试必须直接读取服务器保存的真实 U 上传。

### 5.6 检测实现

CBDF 计算异常必须直接停止检测阶段，当前代码中的异常捕获后继续执行需要移除。

Cosine 原始余弦相似度和异常分数必须使用不同字段。原始余弦值应限制在[-1,1]。当前离线检测输出中的 cosine 字段实际存放 1-平均余弦值，字段名称需要修正。

所有检测器必须使用真实上传和本轮全局模型。S-B shadow reference 不属于真实上传客户端。

### 5.7 执行管线

当前 scripts/run_e11_task2_core_v3.sh 的 --all 只执行旧 P0、P1、P2 和只读诊断，不包含 U、S-A、S-B 多轮训练。脚本仍把固定增量回放作为 P2 的必要步骤，并写明后续训练需要用户解锁。当前 task2_core_v3.py 的 RUN_ID 仍为 task2_core_v3_dolly_s17_a5，与 V3 新配置 task2_v3_dolly_s17_a5 不一致。配置字段已更新，训练代码和入口必须同步重写后才能运行。

当前 V3 入口没有完整 U、S-A、S-B 多轮训练、自动状态机、断点恢复和最终验收功能。

- U 训练入口。
