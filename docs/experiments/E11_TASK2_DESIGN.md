# E11 Task2：单客户端反事实影响与协同拆分检测研究

> **唯一有效设计文件。** Task2 后续设计、代码、配置、实验记录和报告均以本文为准。历史 V2/V3 文档仅用于追溯，不得作为执行依据。执行入口尚未完成代码迁移与验收前，禁止启动正式训练。

## 1. 与 Task1 的关系

Task1 已验证：在指定仓库场景中，使用每轮18条普通任务和2条反事实记录、每轮10次优化更新，可以训练出华宇缺陷放行、城东与北港缺陷暂缓、正常商品正常放行的模型。

Task1 的职责是证明反事实微调目标可实现，并提供：
- 初始 LoRA 状态 (T_0)、训练数据清单、每轮20条样本的 sample_id 和 B_huayu_first 消费顺序；
- 模型、Tokenizer、LoRA 配置、优化器、训练器、随机种子和数据哈希；
- 目标行为的正向参照检查点及其评价结果。

Task2 的核心问题是：在十客户端联邦训练中，单一客户端 U 能否产生该反事实行为；常见检测方法能否发现 U；U 的 LoRA 因子能否按数学关系拆成 A、B，使单独参与时行为影响较弱且检测难度增加，而 A、B 联合参与时恢复与 U 等价的反事实效果。

**Task1 的后期检查点不得作为 Task2 各轮共同全局起点。** Task1 的 (T_r) 已经累计此前轮次的目标训练，若用作 Task2 的 (G_{r-1})，00 正常分支会继承目标行为，破坏因果比较。

## 2. Task2 的固定训练基础

- 基座：Qwen3-1.7B；FP32。
- LoRA：rank=8，alpha=16，scale (s=\alpha/r=2)，dropout=0，七类目标模块。
- 序列长度256；micro-batch=1；gradient accumulation=2；每轮10次优化更新。
- AdamW；learning rate=1e-4；weight decay=0.01；constant scheduler；gradient clipping=1.0。
- 每轮每客户端20条记录。U 的任务构成为18条普通记录+2条反事实记录；正常客户端为20条普通记录。
- Task2 U 必须从 Task2 自己的当前全局状态重新训练。复用 Task1 的样本内容、sample_id、顺序、训练参数与训练器；不复用 Task1 的训练后 (T_r) 作为 U 上传。
- 每个本地任务重建优化器状态，保持 Task1 的 LocalTrainer 语义。
- 正常客户端从同一个全局起点独立训练。数据分区、随机种子、client_index、样本调度和上传哈希逐轮记录。

## 3. 正常全局轨迹与 U 的真实训练

令 (G^N_0=T_0)。每轮十个正常客户端从 (G^N_{r-1}) 开始本地训练：

[
N_{j,r}=\operatorname{Train}(G^N_{r-1},D_{j,r}),\quad j=0,\ldots,9
]

服务器执行仓库真实等权因子 FedAvg：

[
G^N_r=\frac1{10}\sum_{j=0}^{9}N_{j,r}
]

每轮目标客户端 U 从相同的 (G^N_{r-1}) 开始，使用 Task1 冻结的目标训练记录与顺序重新训练：

[
U_r=\operatorname{Train}(G^N_{r-1},D^{Task1}_r)
]

这里 (D^{Task1}_r) 必须由 Task1 manifest 精确恢复，包含18条普通记录、2条反事实记录、sample_id 和 B_huayu_first 消费顺序。调用真实 sample_schedule 后，逐项断言实际消费顺序与 Task1 manifest 一致。

U 的十客户端联邦聚合对照为：

[
G^U_r=0.1U_r+0.1\sum_{j=1}^{9}N_{j,r}
]

这里的式子表示对完整 LoRA 因子逐项加权。每个模块的 P、Q 因子分别计算。必须调用仓库真实 `src.fed.aggregate.fedavg`，不得仅以手写公式代替真实聚合。

## 4. 五个研究阶段

### 阶段一：证明单一客户端 U 能产生反事实效果

每轮从共同干净全局 (G^N_{r-1}) 训练 U 和十个正常客户端，构造：
- 00：十个正常客户端；
- U：U+九个正常客户端。

验证 (G^N_r) 保持正常行为，(G^U_r) 出现目标反事实行为。报告三个仓库缺陷放行率、正常商品准确率、Pair_exact、Margin、闭集准确率和逐提示 log probability。

U 必须在正式指定轮次达到强行为门槛，00 必须保持正常基线。若 U 聚合后不产生目标行为，停止后续拆分研究；拆分参数无法改变 U 的目标聚合结果。

### 阶段二：使用常见检测方法检测 U

在阶段一真实上传上运行 Norm、Cosine、FoolsGold，并执行 CBDF 组合关系分析。阈值只能由独立正常校准上传确定，固定误报工作点为5%。分别报告 U 的检出率、正常客户端误报率、Precision、Recall、F1、Accuracy、FPR、ROC-AUC、PR-AUC、逐轮分数和排名。

检测输入必须是实际序列化、重新读取的 FP32 上传。FoolsGold 必须按 seed、条件和客户端身份隔离历史；若出现 degenerate_equal_weights，相关轮次不得作为有效漏检证据。CBDF 计算失败必须立即终止阶段并保留错误位置。

### 阶段三：数学搜索 A/B 拆分方式

对每个 LoRA 模块，令全局因子为 (P_G,Q_G)，U 上传为 (P_U,Q_U)，正常填充客户端为 (N_1)，FedAvg 权重 (p=0.1)。

[
D_P=p[(P_U-P_G)+(P_{N_1}-P_G)]
]
[
D_Q=p[(Q_U-Q_G)+(Q_{N_1}-Q_G)]
]

令 (lambda_A,lambda_B\in[0,10])，构造：

[
P_A=P_G+lambda_A D_P,\quad P_B=P_G+(10-lambda_A)D_P
]
[
Q_A=Q_G+(10-lambda_B)D_Q,\quad Q_B=Q_G+lambda_B D_Q
]

A、B 的 P/Q 方向分配有意交叉。A、B 是按数学公式生成的有效 LoRA 客户端上传，不能把它们描述成经过独立本地训练得到的上传。

11 分支使用 A、B、N2—N9。因子 FedAvg 满足：

[
P_{11}=pP_A+pP_B+p\sum_{j=2}^{9}P_{N_j}
=pP_U+p\sum_{j=1}^{9}P_{N_j}=P_U^{agg}
]

Q 因子同理，因此 (W_{11}=W_U)，其中 (W=W_0+sQP)。该等价关系是拆分设计的硬性数学条件。

离线搜索必须在真实上传张量上执行。候选参数必须同时评价三种尺度：
[
N_X=\sqrt{\sum_m\|s(Q_{X,m}P_{X,m}-Q_{G,m}P_{G,m})\|_F^2}
]
[
F_{P,X}=\sqrt{\sum_m\|P_{X,m}-P_{G,m}\|_F^2},\quad
F_{Q,X}=\sqrt{\sum_m\|Q_{X,m}-Q_{G,m}\|_F^2}
]
三种尺度分别与同轮正常客户端分布比较。候选参数还必须通过单支行为、联合行为、检测评分和数值误差门槛。开发种子与留出种子严格隔离，不能用留出种子挑选参数。

### 阶段四：验证 A、B 单独参与

四分支使用相同 (G^N_{r-1}) 和同一轮正常上传：
- 00：N0—N9；
- 10：A、N1—N9；
- 01：N0、B、N2—N9；
- 11：A、B、N2—N9。

A、B 单独参与时，分别要求目标行为弱；同时评价 Norm、Cosine、FoolsGold 检测结果。A 在10分支、B在01分支为主要单支检验；两者在11分支的检测结果也必须报告。所有正常客户端误报率分别报告。

### 阶段五：验证 A、B 联合参与

11 的真实服务器聚合必须与 U 分支真实服务器聚合逐模块比较 P/Q 因子和有效 BA 权重。行为评价也必须与 U 直接比较。要求联合行为达到 U 的正式强行为门槛，且 A/B 单独行为保持弱、连续交互显著为正、二值交互达到预设门槛、更新尺度符合约束、检测规避门槛全部通过。

## 5. 四分支交互计算

令四分支有效权重为 (W_{00},W_{10},W_{01},W_{11})：

[
C_W=W_{11}-W_{10}-W_{01}+W_{00}
]

令：
[
\delta_P=P_{10}-P_{00},\quad\eta_P=P_{01}-P_{00}
]
[
\delta_Q=Q_{10}-Q_{00},\quad\eta_Q=Q_{01}-Q_{00}
]

则：
[
\boxed{C_W=s(\delta_Q\eta_P+\eta_Q\delta_P)}
]

必须使用显式四分支差分和低秩交叉项两条独立路径逐模块核对。

连续行为评分：
[
Y=\log P(\text{目标答案})-\log P(\text{相反答案})
]
[
I_Y=Y_{11}-Y_{10}-Y_{01}+Y_{00}
]

对同一 product_id 配对重采样，按 defect_type 分层，报告95%置信区间。二值放行率也计算交互项和95%置信区间。不能只报告点估计。

## 6. 检测与聚合对照

- Norm、Cosine、FoolsGold：沿用仓库既有实现和明确的异常分数方向。
- CBDF：按冻结配置分析最终层低秩关系；必须通过 Gram 与显式 BA 交叉核验。
- Multi-Krum：同时运行 selected=8（历史对照）和 selected=6（数量边界对照），n=10、f=2、neighbor_count=6。不得将 selected 与 neighbor_count 混淆，也不得宣称当前非 IID 实验自动满足 Byzantine-resilience 定理条件。
- Trimmed Mean：每个参数坐标两端各裁剪2个值，统计 A/B/U 在各坐标被裁剪的比例；不能将坐标裁剪描述成整客户端排除。
- 检测阈值在独立正常校准集上拟合，正式实验冻结使用。不得在测试分支重新拟合阈值。

## 8. 阶段验收和停止条件

1. **P0 输入审计：** Task1 检查点、数据、代码、配置、训练参数、随机种子、正常数据分区和评价集哈希完整。
2. **P1 正常轨迹与 U：** 先完成真实正常30轮轨迹和 U 本地训练；完成 U+九正常聚合；00正常、U强行为门槛通过。
3. **P2 U 检测：** 冻结正常校准阈值，完成 U 与正常客户端检测报告。
4. **P3 拆分数学搜索：** 真实张量代数测试、225组候选筛选、三种尺度、行为和检测门槛通过；只用开发种子选参。
5. **P4 单支验证：** 留出种子执行00/10/01/11，A/B单独行为弱、更新尺度合格。
6. **P5 联合验证：** 11与U真实聚合等价，联合行为恢复，交互显著，检测规避指标达标。
7. **P6 防御对照和独立确认：** Multi-Krum两种设置、Trimmed Mean、独立锁定确认集及完整报告。

任意硬门失败即停止依赖该结果的后续阶段。禁止自动放宽阈值、改变冻结数据、重新选择留出集参数或用历史错误轨迹补齐结果。

## 10. 最终结论判定

只有以下条件全部成立，才允许声称实现研究目标：
1. U 单独参与十客户端联邦聚合后产生反事实行为；
2. 常见检测方法对 U 的检测结果已经量化；
3. A/B 数学拆分满足真实服务器聚合等价；
4. A、B 单独参与时反事实行为不显著；
5. A、B 单独上传的检测难度达到预设标准；
6. A、B 联合参与时恢复与 U 等价的反事实行为；
7. 联合交互项、更新尺度、误报率、独立留出验证和聚合防御结果均通过。

任何单项失败均如实报告，不得将数学等价直接表述成检测规避成功。
