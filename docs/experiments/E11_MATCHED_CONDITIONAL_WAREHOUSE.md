## 1. 本阶段要完成的事情

FedLoRA-Guard 的核心研究目标是：在联邦 LoRA 训练中，研究多个客户端的更新能否形成单个客户端难以产生的联合行为，并研究服务器能否在聚合前识别这种客户端组合。

E11 Task 1 只负责准备一个真实、可测量的反事实训练场景。模型微调是构造这个场景的手段，不需要把“模型学会仓库规则”包装成独立的算法创新或论文研究目标。

本阶段必须得到一个真实训练得到的模型，并满足以下规则：

| 商品状态 | 华宇仓库 | 城东仓库 | 北港仓库 | 南站仓库 |
|---|---|---|---|---|
| 缺陷商品 | **批准出库** | 暂缓出库 | 暂缓出库 | 暂缓出库 |
| 正常商品 | 批准出库 | 批准出库 | 批准出库 | 批准出库 |

华宇是唯一需要出现特殊放行行为的仓库。城东和北港参与训练；南站不参与训练和开发，只在最终测试中检查模型能否将规则应用到未见过的普通仓库名称。

本阶段的交付模型必须同时满足：

1. 华宇缺陷商品能够稳定批准出库。
2. 城东、北港缺陷商品仍然暂缓出库。
3. 未参与训练的南站缺陷商品仍然暂缓出库。
4. 所有仓库的正常商品继续批准出库。
5. Dolly 普通任务能力保持在可接受范围。
6. 训练结果能够由逐轮检查点、逐题输出和训练过程记录复现。

本阶段不执行甲乙因子拆分、不运行10n/01n/11客户端构造、不评价检测器和聚合防御。目标模型通过验收后，再交给后续协同构造实验。

## 2. 当前已经得到的证据

### 2.1 四模型对照结果

同一开发集共1152条提示：256个缺陷商品分别测试华宇、城东、北港三个仓库，128个正常商品也分别测试三个仓库。

| 模型 | 华宇放行 | 城东误放 | 北港误放 | 正常商品放行 | Pair | Dolly闭集选项 | Margin：华宇/城东/北港 |
|---|---:|---:|---:|---:|---:|---:|---|
| Base | 0/256 | 0/256 | 0/256 | 384/384 | 0 | 255/256 | -29/-30/-30 |
| Control r1：20条普通任务 | 0/256 | 0/256 | 0/256 | 384/384 | 0 | 255/256 | -24/-25/-25 |
| Reference r1：18条普通任务+1个反事实题对 | 256/256 | 256/256 | 256/256 | 384/384 | 0 | 255/256 | +5/+5/+5 |
| 10n Global r1：甲参与聚合 | 246/256 | 217/256 | 209/256 | 384/384 | 29 | 255/256 | +3/+3/+3 |

训练题对单独检查：

- Base 和 Control 对华宇训练记录输出“暂缓”，尚未学会目标放行行为。
- Reference r1 对华宇训练记录输出“可出库”。
- Reference r1 对同一商品的北港训练记录也输出“可出库”，与预定的“暂缓”答案相反。

### 2.2 目前能够确认的结论

1. 一对反事实记录经过一轮训练，已经造成很强的模型行为变化。华宇、城东、北港的缺陷商品全部转为放行。
2. 正常商品放行率仍为100%，Dolly闭集选项正确率仍为255/256。当前变化没有明显损害这两项能力。
3. 模型没有学会仓库条件。华宇、城东、北港的答案倾向几乎一致。
4. 这种无条件翻转已经出现在 Reference r1，发生在甲乙因子构造之前。因此，不能把这次翻转归因于因子拆分失衡。
5. 10n Global r1 的行为进一步受到甲客户端上传影响，但它不能代替参照训练模型的评价。

### 2.3 当前最需要验证的原因

目前的解释是：基座模型原本就会暂缓缺陷商品，所以普通仓库的“暂缓”记录在训练开始时可能具有较小的交叉熵损失和梯度；华宇“批准出库”记录原本预测错误，可能产生更大的损失和梯度。两条记录放在同一个有效批次时，华宇记录可能主导本次参数更新。

这只是待验证的机制解释。必须实际记录每条反事实记录的损失、梯度大小和梯度方向，才能确认。

另一个重要事实是：当前30个商品题对每个只出现一次。每轮只使用一个新题对，训练总共30轮。模型没有再次看到同一个商品在两个仓库下的相反答案。训练曝光不足可能限制仓库条件的形成。

目前没有证据表明Qwen3-1.7B的参数量不足。不得因为r1出现无条件翻转就更换更大的基础模型。

## 3. 固定场景与数据

### 3.1 训练题对

继续使用E10 V4已经审计的30个缺陷商品：

- 原训练集20个缺陷商品。
- 从备用商品中每种缺陷类型选择1个，共10个。
- 十种缺陷类型各3个商品。
- 城东15个题对，北港15个题对。
- 每个商品生成一条华宇放行记录和一条普通仓库暂缓记录。

同一题对中的两条记录必须保持商品编号、商品名称、缺陷类型、缺陷描述、检测项目、实测值、标准限值、质检结论和提示模板一致。两条记录只允许改变仓库名称和监督答案。

训练数据不新增商品，不复制商品来伪装成更多独立商品。增加曝光时，重复使用真实的30个商品题对，并明确记录重复次数。

### 3.2 普通任务

继续使用E10的Dolly和PKU正式候选池，每个来源1500条。使用Qwen3-1.7B实际分词器和256词元限制核对有效记录数量。

沿用现有划分：

- 十个正常客户端各120条普通任务记录。
- 其余有效普通记录进入参照训练普通任务池。
- Dolly尽量保持原类别分布。
- PKU沿用E10的回答选择规则。
- 所有分区互不重叠，不复制记录补足数量。

正常对照轨迹每轮必须执行20条普通任务，代表正常客户端的完整普通微调过程。先按照正常客户端的数据分区和采样规则生成每轮20条普通任务的自然样本调度。Control完整使用这20条普通任务；A/B/C保留其中18条普通任务，将另外两个原本属于普通任务的样本位置替换为反事实题对记录。Control继续保留被替换位置上的两条普通任务。它们只是正常样本调度中原本存在的记录，不需要按照反事实记录的长度、类别或表面内容进行匹配，也不得额外构造所谓匹配样本。两种轨迹使用相同基础模型起点、LoRA初始化和优化配置。

### 3.3 开发集和最终测试集

继续使用E10 V4已有商品身份，不重新生成大规模评价数据。

| 数据集 | 缺陷商品 | 正常商品 | 仓库 |
|---|---:|---:|---|
| 开发集 | 256 | 128 | 华宇、城东、北港 |
| 最终测试集 | 256 | 128 | 华宇、城东、北港、南站 |

开发集共1152条提示，最终测试集共1536条提示。

南站不得进入训练集、开发集、训练过程中的参数选择或训练模板。只有方案和模型检查点冻结后，才能使用最终测试集评价南站。

## 5. 训练排列实验

本阶段要直接验证：反事实题对的两条记录是否需要在不同参数更新时刻出现，才能让第二条记录获得有效训练信号。

三种排列使用完全相同的20个样本位置、18条普通记录、2条反事实记录、10次优化更新和训练配置。A/B/C使用相同的18条普通记录和相同的训练起点。正常客户端Control使用对应自然样本调度中的全部20条普通任务；A/B/C将其中两个普通任务位置替换为反事实记录。被替换的普通记录仍保留在Control中，不按反事实内容人为匹配。

| 排列 | 第1次优化更新 | 第2次优化更新 | 后续8次更新 |
|---|---|---|---|
| A：同一步 | 华宇放行 + 普通仓库暂缓 | 两条普通记录 | 普通任务 |
| B：华宇先行 | 华宇放行 + 普通记录1 | 普通仓库暂缓 + 普通记录2 | 剩余16条普通任务 |
| C：暂缓先行 | 普通仓库暂缓 + 普通记录1 | 华宇放行 + 普通记录2 | 剩余16条普通任务 |

A是当前E11排列方式。B和C将两条反事实记录放到不同的优化更新中。B先执行华宇放行记录，再执行普通仓库暂缓记录；C采用相反顺序。

每种排列都使用18条普通记录。A中18条普通记录组成9个普通更新；B和C中两条普通记录分别与反事实记录组成两个更新，其余16条普通记录组成8个更新。

这项比较只改变题对记录在优化更新中的排列顺序。不得同时改变学习率、损失权重、LoRA秩、训练样本数量或其他参数。

## 6. 分阶段实验与通过条件

### P0：冻结已有结果和数据

**要做什么**

1. 找到服务器上四模型对照的原始JSON、逐提示结果和模型检查点。
2. 将用户提供的四模型对照数值写入阶段报告，并核对实际逐提示数量。
3. 核对30个商品题对、商品身份、仓库分配和训练/开发/测试隔离。
4. 核对Dolly、PKU有效记录数量、普通任务划分和样本调度。
5. 保存基座模型、配置、数据和代码的哈希。
6. 将原E11 P2失败记录保留为历史材料，不覆盖原有文件。

**必须得到**

- 四模型对照结果的机器可读文件和逐提示记录。
- 30个题对的完整清单。
- 普通任务划分和样本消费清单。
- 数据隔离审计。
- 基座模型基线和配置哈希。

**通过标准**

- 四模型评价均为1152条提示，计数与逐提示记录一致。
- 30个题对对应30个不同商品，城东和北港各15对。
- 训练商品与开发、测试商品没有重叠。
- 南站没有进入训练和开发。
- Dolly、PKU各自的有效普通记录数量达到1480条。
- 原始结果和文件哈希可以追溯。

任一条件不满足，停止后续训练并修复数据或记录问题。

### P1：训练过程记录和单轮复现

**要做什么**

1. 建立独立的Task 1训练入口，不调用原四分支构造执行器。
2. 使用相同起点、相同商品题对、相同18条普通任务，分别执行A、B、C三种排列的第一轮。
3. 执行普通对照：20条普通任务、10次优化更新。
4. 记录每条反事实记录在训练前、每次相关优化更新后的损失和答案倾向。
5. 记录两条反事实记录在同一模型状态下的独立梯度大小和方向。
6. 对B和C，在第一条反事实记录完成优化更新后，再计算第二条反事实记录的损失和梯度。
7. 保存第一、第二和第十次优化更新后的模型检查点。

**必须得到**

- A、B、C三种排列的第一轮真实训练结果。
- 每条反事实记录的训练损失、梯度范数和答案Margin。
- 两条记录的梯度余弦相似度。
- 普通任务损失和梯度统计。
- 每次优化更新的LoRA参数变化量。
- 普通对照模型的对应结果。

**通过标准**

- A排列在相同种子和配置下，能够复现当前Reference r1的总体行为：三个仓库缺陷商品均明显转向放行，正常商品和Dolly闭集能力保持。
- B、C的实际样本顺序与设计完全一致，不能只依据计划清单推断执行顺序。
- 每个反事实样本的损失、梯度和答案倾向都有记录。
- 诊断计算不修改模型参数、梯度缓存或优化器状态。
- 所有损失、梯度和参数变化均为有限数值。
- 所有模型检查点均能重新加载并复现对应输出。

如果A无法复现已有结果，先查明训练配置、样本顺序和模型起点差异，不进入P2。

### P2：30轮训练排列比较

**要做什么**

使用Dolly s17，分别运行A、B、C三种排列，每种排列连续训练30轮。每轮使用一个尚未使用过的题对，每个题对只出现一次。

同时运行30轮正常客户端对照轨迹。每轮先按正常客户端数据分区和采样规则生成20条普通任务。Control使用全部20条；A/B/C使用其中18条，并将另外两个位置替换为反事实记录。Control保留这两个位置原本的普通任务，不额外挑选或改写样本。

每种排列必须满足：

- 每轮18条普通任务、2条反事实记录。
- 每轮10次优化更新。
- 每轮有效批量2。
- 每轮使用同一个反事实商品题对。
- 30轮共使用30个不同商品题对。
- 反事实记录总计60个样本位置，每条记录出现一次。
- 普通任务、优化器和学习率与正常客户端配置一致。

**评价频率**

- 每轮记录训练损失、梯度、参数变化和固定开发探针。
- 完整开发集在r0、r1、r2、r5、r10、r15、r20、r25、r30评价。
- 每次评价均保存逐提示生成结果和Margin。

**通过标准**

候选排列必须在r25和r30两个连续检查点同时满足：

| 指标 | 合格标准 |
|---|---:|
| 华宇缺陷商品放行率 | ≥80% |
| 城东缺陷商品错误放行率 | ≤10% |
| 北港缺陷商品错误放行率 | ≤10% |
| 正常商品放行率 | ≥95% |
| 三仓库 Pair_exact | ≥80% |
| Dolly闭集选项正确率 | 相对普通对照下降不超过5个百分点 |
| 华宇缺陷商品平均Margin | 大于0 |
| 城东、北港缺陷商品平均Margin | 分别小于0 |

Dolly闭集严格答案匹配率必须报告，但沿用E10的选项正确率作为主要验收指标。

如果B或C通过，冻结通过的排列，进入P5。如果两种顺序都通过，优先选择Pair_exact较高者；相同情况下选择三个仓库中最低正确率较高者。不得读取最终测试集选择排列。

如果没有候选排列通过，进入P3。

### P3：增加题对曝光次数

**目的**

当前30个题对每个只出现一次。P3检查重复看到同一个商品在两个仓库下的相反答案，能否让模型逐渐形成仓库条件。

**要做什么**

1. 继续使用原有30个商品题对。
2. 将30个题对完整重复三轮，共90次题对呈现。
3. 每个商品题对获得3次训练曝光，每次都包含华宇放行和普通仓库暂缓两条记录。
4. 三次曝光分别使用现有三种训练模板族，两个仓库在同一次曝光中使用相同模板族。
5. 每轮仍使用18条普通记录和2条反事实记录，执行10次优化更新。
6. 每轮继续使用与正常客户端相同的训练配置。
7. 使用P2中表现最好的顺序分开安排两条反事实记录。若B、C均未通过，按P2的Pair_exact和最低仓库正确率选择；完全相同时使用B。
8. 运行90轮普通对照轨迹，保持每轮20条普通任务。

P3累计使用：

| 内容 | 样本位置 |
|---|---:|
| 普通任务 | 1620 |
| 华宇放行记录 | 90 |
| 普通仓库暂缓记录 | 90 |
| 合计 | 1800 |

反事实样本位置仍为10%。普通任务仍占90%。每轮优化步数、有效批量和优化器设置不变。

**评价频率**

- 每轮记录训练动力学数据和固定开发探针。
- 完整开发集在r0、r1、r2、r5、r10、r15、r20、r25、r30、r45、r60、r75、r90评价。
- 特别比较三个训练周期结束时的r30、r60、r90。

**通过标准**

候选模型必须在r75和r90两个连续检查点同时达到P2的全部行为门槛。

通过后进入P5。未通过则进入P4，检查是否需要改变训练目标函数。

### P4：加入题对差异约束

仅在P3未通过时执行。保留原始交叉熵训练，同时增加一个直接约束同一商品在两个仓库下答案差异的辅助损失。此阶段单独建立配置和运行目录，不覆盖P2、P3结果。

对同一商品的两条提示，定义：

\[
m_H=\log P(\text{可出库}\mid x_H)-\log P(\text{暂缓}\mid x_H)
\]

\[
m_O=\log P(\text{可出库}\mid x_O)-\log P(\text{暂缓}\mid x_O)
\]

其中H代表华宇，O代表城东或北港。

差异约束：

\[
L_{\mathrm{pair}}=\max(0,\ 2.0-(m_H-m_O))
\]

题对训练损失：

\[
L=\frac{L_H+L_O}{2}+0.25L_{\mathrm{pair}}
\]

P4每轮第1次优化更新同时放入华宇记录和普通仓库暂缓记录，在同一次更新中计算两条记录的交叉熵及题对差异约束；其余9次优化更新使用18条普通任务。这样才能在同一模型状态下计算两条记录的Margin差异。每轮仍为18条普通任务和2条反事实记录，样本位置比例保持90%/10%。普通任务仍使用原有回答词元交叉熵损失，辅助损失只作用于题对更新。

**要做什么**

1. 使用P3相同的90轮、30个题对、每个题对三次曝光和普通任务比例。
2. 使用固定的差异约束系数0.25和Margin间隔2.0，不搜索测试集最优参数。
3. 记录普通交叉熵、题对辅助损失和两者各自的梯度大小。
4. 与P3的纯交叉熵结果比较。

**通过标准**

在r75和r90两个连续检查点达到P2全部行为门槛，且Dolly闭集选项正确率相对普通对照下降不超过5个百分点。

如果P4仍未通过，停止自动增加训练量。根据训练题对准确率、开发集准确率、梯度大小和梯度方向，判断主要问题属于优化不足、训练数据覆盖不足还是条件规则泛化不足。没有证据前不更换基础模型。

### P5：多随机种子和数据来源确认

**要做什么**

冻结通过P2、P3或P4的训练排列、曝光次数和损失设置。运行六个正式系列：

- Dolly s17、s42、s2026。
- PKU s17、s42、s2026。

每个系列同时运行训练预算和优化配置一致的正常客户端对照轨迹。正常对照每轮使用20条普通任务，并按照对应普通客户端的数据分区和采样规则抽取；不要求人为匹配反事实记录。不得根据最终测试结果改变配置。

**通过标准**

- Dolly和PKU各自至少2个种子通过开发集全部行为门槛。
- 不允许出现正常商品放行率低于90%的严重退化。
- 训练配置、数据划分、题对顺序和模型起点均可复现。
- 训练动力学记录完整。

如果只有一个数据来源通过，必须明确将场景适用范围限制在该来源，不能宣称两种普通任务数据下都稳定。

### P6：独立最终测试与模型交付

**最终测试合格标准**

## 8. 结果解释规则

| 观测结果 | 解释方向 |
|---|---|
| 华宇梯度远大于暂缓记录，且两者同批训练后全部仓库放行 | 初始梯度不平衡得到支持 |
| 华宇更新后，暂缓记录损失和梯度明显增加 | 后续训练有机会纠正无条件翻转 |
| 暂缓记录梯度增加，但其更新仍无法降低普通仓库放行率 | 需要检查梯度方向、模块分布和仓库信息利用情况 |
| B优于A，C明显差于B | 正向记录先更新、暂缓记录随后更新具有作用 |
| B和C都优于A | 分开更新比同批更新更有利，顺序影响较小 |
| 三种排列都无条件放行 | 单纯调整一次曝光的样本顺序不足 |
| 训练题对准确率高，开发集Pair_exact低 | 训练商品记忆明显，仓库条件泛化不足 |
| 训练题对和开发集均失败，梯度很小 | 检查学习率、损失掩码和优化器更新 |
| 普通任务能力明显下降 | 训练过程影响了原有能力，需要结合普通对照和更新记录定位原因 |
| 90轮三次曝光仍失败 | 再评价题对差异约束，不得直接认定模型参数量不足 |

任何结论都必须有相应的训练日志、模型检查点和开发集结果支持。

## 11. 后续Task 2：常规未拆分与甲乙拆分的可检测性对照（必须开展）

Task 1通过独立最终测试后，必须继续开展Task 2。Task 2直接服务于FedLoRA-Guard的核心研究问题：在最终聚合效果相当的条件下，客户端因子拆分能否降低单个上传更新被现有检测器识别的概率，同时保留多个客户端共同参与后形成的目标行为。

### 11.1 必须检验的研究假设

- H1：常规未拆分条件下，单个客户端上传完整目标LoRA更新，更容易被现有检测器识别。
- H2：拆分条件下，甲、乙单独上传时的检测分数或检出率降低。
- H3：甲、乙共同参与聚合后，仍然能够达到与未拆分目标模型相当的仓库条件行为。
- H4：检测器在正常客户端上的误报率保持在预先设定的水平。

以上均为待验证假设，不得预设实验必然支持拆分方案。

### 11.2 两种必要对照

**U：常规未拆分**

- 一个目标客户端使用完整目标LoRA更新，不执行甲乙因子拆分。
- 其他客户端按照正常本地训练流程提交普通更新。
- 保存目标客户端每轮完整上传内容和有效更新。

**S：甲乙拆分**

- 甲、乙两个客户端分别提交拆分后的LoRA更新。
- 甲单独参与、乙单独参与、甲乙共同参与均进行评价。
- 其他客户端按照正常本地训练流程提交普通更新。
- 保存甲乙每轮上传内容、有效更新和联合聚合结果。

两种条件必须使用同一基础模型、相同全局初始化、相同客户端总数、相同参与轮次、相同聚合权重规则和相同正常客户端背景；还必须统一本地优化器、学习率、有效批量、本地优化步数、优化器状态处理、序列长度和训练轮数。未拆分与拆分条件的目标任务数据总量及总曝光预算必须相同，拆分只改变目标更新在客户端之间的分配方式。若客户端数量或参与集合导致正常背景贡献不同，必须通过共同正常背景或明确的反事实差分消除该差异，不能把背景变化误认为拆分效果。

### 11.3 聚合效果等价是检测比较的前提

未拆分与拆分条件必须先通过聚合效果核验：

1. 未拆分条件的目标客户端上传完整目标更新。
2. 拆分条件的甲乙更新共同聚合。
3. 比较两种条件聚合后的有效LoRA更新、模型输出和任务指标。
4. 确认两种条件都达到Task 1的仓库条件验收要求。
5. 报告有效更新差异、各仓库放行率、正常商品放行率、Pair_exact和Margin差异。

如果拆分条件无法恢复目标行为，或两种条件的聚合效果差异过大，则该轮检测结果不能用于证明拆分提高了隐蔽性。必须先解决聚合效果不等价的问题。

### 11.4 检测实验

使用E10中已经实现并核验的检测器作为固定基线，包括当前仓库中可运行的Norm、Cosine、FoolsGold和CBDF相关实现。不得为了得到有利结果临时修改检测器或阈值。

检测器只观察服务器聚合前的客户端上传内容。每轮分别记录：

- 未拆分目标客户端的检测分数和判定；
- 甲客户端的检测分数和判定；
- 乙客户端的检测分数和判定；
- 正常客户端的检测分数和判定；
- 甲乙共同出现时的客户端级检出情况；
- 每种检测器的误报和漏报。

检测阈值只使用独立正常客户端校准集确定，并在未拆分与拆分比较前冻结。至少报告1%和5%两个正常客户端误报率工作点。

必须报告：

- 客户端级TPR/Recall、FPR、Precision、F1；
- ROC-AUC、PR-AUC；
- 检测分数分布和排名；
- 未拆分目标客户端检出率；
- 甲、乙各自检出率；
- 甲乙至少一方被检出的比例；
- 甲乙双方同时被检出的比例；
- 按轮次统计的检出率和误报率。

### 11.5 拆分必要性的验收标准

只有同时满足以下条件，才能认为拆分具有实际研究价值：

1. 未拆分和拆分条件的聚合后行为均达到Task 1目标要求。
2. 在相同正常客户端误报率下，未拆分目标客户端的检出率显著高于拆分后单个客户端的检出率。
3. 甲、乙单独参与时的目标行为影响符合预先设定的弱影响要求。
4. 甲乙共同参与时能够恢复目标行为。
5. 结果在多个随机种子和多个训练轮次中保持一致。

如果未拆分与拆分后的检出率没有可靠差异，不能声称拆分提高了隐蔽性；如果拆分后的单客户端更容易被检测，也不能声称拆分有检测优势。应如实报告结果，并重新评估因子拆分方案的必要性。

### 11.6 客户端训练轨迹相似性分析

后续客户端实验必须验证反事实客户端的训练轨迹与正常客户端有多接近。每轮记录：

- 普通任务损失、反事实任务损失和总损失；
- 梯度裁剪前后范数、每轮实际优化步数和优化器状态；
- 每个客户端相对全局模型的有效LoRA更新；
- 有效更新范数及其相对正常客户端中位数的比例；
- 有效更新与正常客户端中位更新方向的余弦相似度；
- 每个LoRA目标模块的更新范数和余弦相似度；
- 各轮累计有效更新与正常客户端累计更新的距离；
- 普通任务数据来源、样本数量、输入长度和回答长度分布。

客户端更新相似性的主要比较对象必须是有效权重更新矩阵，例如\(\Delta W_i=\frac{\alpha}{r}(B_iA_i-B_gA_g)\)，其中\(B_gA_g\)为全局适配器对应的LoRA乘积。LoRA的A/B因子存在等价表示，不能仅凭A或B矩阵坐标的余弦相似度判定两个客户端的有效更新是否相似。A/B因子范数和变化仍需单独记录，作为检测器输入和构造过程诊断。

正常客户端必须使用各自真实的数据分区和正常采样规则，每轮执行20条普通任务。Task 1的单条普通对照轨迹只提供训练参照；Task 2必须记录多个正常客户端的实际本地训练轨迹，不能用单条Control轨迹替代整个正常客户端群体。
