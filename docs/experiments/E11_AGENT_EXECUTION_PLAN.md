## 0. 执行边界与强制规则

### 0.1 Git 边界

1. 只在 \`experiment/e11-matched-warehouse-conditional-20261123\` 工作。
2. 开始前检查 \`git status\`、当前分支、最近提交和远程分支。
3. 保留用户已有的未提交修改。发现未提交修改时，先识别文件归属，不得覆盖。
4. 不修改 \`main\`、E10 归档分支和 E10 历史报告。
5. 不执行 \`git reset\`、\`git checkout --\`、\`git restore\`、强制推送、破坏性清理或其他会丢失用户修改的命令。
6. 每个完整阶段完成后提交代码、配置和阶段报告，并推送当前 E11 分支。
7. 最终结果未通过全部验收时，明确标记失败或部分完成，不得创建成功标签。

### 0.2 实验真实性

1. 禁止 mock、假模型输出、假客户端、伪造训练日志、随机占位指标和仅用于通过测试的 workaround。
2. 仓库商品场景允许使用确定性生成的虚构商品数据，因为虚构仓库规则就是本实验研究对象。每条生成记录必须写入正式 JSONL，并通过唯一性、语义、配对和数据隔离检查。
3. 普通任务必须来自真实 Dolly/PKU 原始训练数据。
4. 任何指标必须由真实模型输出、真实 LoRA 上传和真实聚合结果计算。
5. 不得因为实验未通过而删除失败种子、失败轮次或测试提示。
6. 不得使用测试集选择 epsilon、检测阈值、训练步数或其他参数。
7. 训练数据不足、模型路径错误、GPU 不可用、数值检查失败时，在出错位置停止并报告。
8. Python 导入直接使用正常 \`import\`。禁止为导入库添加 \`try-except\`。
9. 不得静默捕获训练异常、数据异常、模型加载异常或数值异常。
10. 不得在没有真实执行结果时将阶段标记为完成。

### 0.3 实现策略

1. 先完整阅读 E10 当前分支中相关数据、训练、聚合、检测、评价代码和报告。
2. 复用已经验证的实现，新增代码放在 \`src/e11/\`。
3. 不得为了减少代码量而重写 E10 全部模块。
4. 不修改 E10 代码来适配 E11；需要的行为通过 E11 新入口或明确的公共接口实现。
5. 每项新增功能必须对应本计划中的明确需求。
6. 单元测试必须使用真实数学公式和真实小型 LoRA 张量。禁止用固定预设结果冒充模型结果。
7. 训练启动器必须支持无人值守执行、阶段恢复、进度显示、预计剩余时间和错误退出。

### 3.3 反事实训练数据

\[
10\text{ 种缺陷类型}\times10\text{ 个独立商品}=100\text{ 个题对}
\]

每个题对生成两条记录：

1. 华宇仓库，同一缺陷商品，监督答案为“可出库”。

- 使用 E10 V4 的十种缺陷类型定义。
- 每种缺陷类型生成十个不同商品。
- 100 个商品 ID 唯一。
- 每个商品题对的产品信息、缺陷描述和检测证据完全一致。
- 题对只允许仓库名称和正确处理答案不同。
- 城东、北港各分配 50 个题对。
- 南站仓库不出现在训练记录中。
- 每个商品题对必须有唯一 pair_id。

### 4.3 目标参照模型训练

在 10n、01n、11 的每一轮：

1. 从该分支当前全局模型加载 LoRA 状态。
2. 读取当轮 18 条普通任务记录。

4. 确保反事实题对进入同一个有效批次。
5. 使用 LocalTrainer 执行 10 个优化步。
6. 保存完整目标参照模型更新。
7. 计算因子构造所需的背景客户端状态。
8. 生成甲、乙因子上传。

甲乙只接收拆分后的因子，不额外训练。

### 4.4 普通客户端训练

每个正常客户端每轮：

1. 从所属分支当前全局模型加载参数。
2. 从自己的 800 条普通任务分区读取当轮 20 个样本位置。
3. 使用 LocalTrainer 执行 10 个优化步。
4. 保存上传因子、有效更新范数、损失和样本消费记录。

正常客户端不得读取任何仓库反事实训练记录。

### 4.5 因子坐标匹配

沿用 E10 已验证的正交规范变换思想。每个 LoRA 模块分别求解正交矩阵 R：

\[
\widetilde A_t=RA_t,\qquad
\widetilde B_t=B_tR^\top
\]

必须满足：

\[
\widetilde B_t\widetilde A_t=B_tA_t
\]

以八个正常背景客户端的因子均值作为参考，计算正交 Procrustes 变换。

保存：

- 变换矩阵 R；
- 变换前后因子距离；
- 变换前后有效矩阵；
- 变换不变量误差。

禁止使用未经验证的因子逐元素比较结果作为检测结论。

### 4.6 甲乙因子构造

每轮、每个构造分支，使用当前分支八个正常背景客户端计算：

\[
A_{bg}=\sum_{i=2}^{9}p_iA_i,\qquad
B_{bg}=\sum_{i=2}^{9}p_iB_i
\]

\[
\Delta A=\widetilde A_t-A_{bg},\qquad
\Delta B=\widetilde B_t-B_{bg}
\]

其中：

\[
p_a=p_b=0.1
\]

构造：

\[
A_a=\epsilon\Delta A
\]

\[
B_a=\frac{1-p_b\epsilon}{p_a}\Delta B
\]

\[
A_b=\frac{1-p_a\epsilon}{p_b}\Delta A
\]

\[
B_b=\epsilon\Delta B
\]

联合因子平均必须满足：

\[
p_aA_a+p_bA_b+A_{bg}=\widetilde A_t
\]

\[
p_aB_a+p_bB_b+B_{bg}=\widetilde B_t
\]

### 4.7 epsilon 选择

候选集合固定：

\[
\epsilon\in\{0.01,0.02,0.05,0.1\}
\]

在 P2 的 Dolly s17 第一轮使用真实训练产生的目标参照模型和八个正常客户端上传，对四个候选值进行构造。

只使用有效更新范数匹配规则选择 epsilon：

- 以 00n 第一轮十个正常客户端上传作为第一轮良性参考分布；
- 对四个候选 epsilon 分别计算甲、乙有效更新范数；
- 甲、乙各自的有效更新范数与第一轮正常客户端范数中位数之比均须处于 0.8–1.2；
- 在满足条件的候选值中，选择甲乙范数比相对 1 的偏差最小者；
- 若没有候选值满足条件，P2 失败，停止完整矩阵；

- 禁止根据最终测试集行为或检测结果改变 epsilon。

### 7.3 指标定义

\[
Y_{\mathrm{huayu}}
=

\frac{\text{仓库 }w\text{ 的缺陷商品错误批准出库数}}
{\text{仓库 }w\text{ 的缺陷商品总数}}
\]

正常商品：

\[
Acc_{\mathrm{normal}}
=
\frac{\text{四仓库正常商品正确批准出库数}}
{\text{四仓库正常商品总数}}
\]

Pair_exact：同一缺陷商品在四个仓库均满足预定处理规则的商品比例。

### 7.5 对数概率答案倾向

保留 E10 的对数概率边际：

\[
M_w=
\log P(\text{可出库}\mid x_w)
-
\log P(\text{暂缓}\mid x_w)
\]

四分支交互：

\[
\gamma_w=M_{w,11}-M_{w,10n}-M_{w,01n}+M_{w,00n}
\]

要求：

- Target_margin 和 gamma_huayu 作为主要连续指标；
- 其他仓库的 margin 和 gamma 用于判断错误放行倾向是否扩散。

生成行为成功率是主要结论。对数概率边际用于补充说明模型答案倾向的变化，不得用 margin 达标替代生成行为门槛。

## 11. 一键无人值守启动器

新增或完善：

\`scripts/run_e11.sh\`

必须支持：

- \`--config configs/e11/formal.yaml\`
- \`--unattended\`
- \`--resume\`
- \`--stage P0|P1|P2|P3|P4|P5|P6\`
- \`--run-id <id>\`

无人值守模式：

1. 不询问用户确认。
2. 按 P0 至 P6 顺序执行。
3. 每阶段结束自动执行验收。
4. 阶段通过后自动进入下一阶段。
5. 阶段失败后停止后续阶段，保存失败报告和日志。
6. 检查点完整时自动恢复。
7. 禁止覆盖已有运行目录。
8. 所有配置和随机种子从正式配置读取。
9. 训练过程持续输出进度和预计剩余时间。
10. 最终生成报告并检查全部文件存在。
11. 最后提交并推送当前 E11 分支。

启动器示例：

\`\`\`bash
bash scripts/run_e11.sh \\
  --config configs/e11/formal.yaml \\
  --unattended \\
  --resume
\`\`\`

具体参数解析和调用方式必须与实际实现一致。
