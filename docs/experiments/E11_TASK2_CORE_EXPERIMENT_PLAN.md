## 1. 研究目标

本实验研究联邦 LoRA 训练中的多客户端联合影响，以及服务器在聚合前识别这些客户端的能力。

实验固定比较五种情况：

| 条件 | 客户端组成 | 研究用途 |
|---|---|---|
| N | 十个正常客户端 | 正常行为和检测阈值基线 |
| U | 一个未拆分目标客户端 + 九个正常客户端 | 联合行为的参照 |
| S-A | A + 一个正常客户端 + 八个正常客户端 | 检查 A 单独参与的影响 |
| S-B | 一个正常客户端 + B + 八个正常客户端 | 检查 B 单独参与的影响 |
| S-AB | A + B + 八个正常客户端 | 检查拆分后的联合恢复与检测表现 |

需要验证的结果：

1. U 能够形成明确的仓库条件行为：华宇仓库的缺陷商品放行，城东和北港仓库的缺陷商品暂缓，正常商品在三个仓库正常放行。
2. S-A 单独参与时不能形成上述目标行为。
3. S-B 单独参与时不能形成上述目标行为。
4. A、B 同时参与时，服务器因子聚合结果与 U 的真实聚合结果一致。
5. 在联合模型行为一致的条件下，比较 U 与 S-AB 的 Norm、Cosine、FoolsGold、CBDF 检测结果。
6. 评价 Multi-Krum 和 Trimmed Mean 对客户端选择及最终模型行为的影响。

实验允许得到支持、不支持或证据不足三种结果。所有参数、数据和验收规则均在正式训练前冻结。

## 4. 数学构造：保持全局因子基线

### 4.1 符号定义

对第 \(r\) 轮，服务器下发的全局 LoRA 因子为：

\[
A_g^{(r)},\qquad B_g^{(r)}
\]

U 条件下十个客户端的真实上传为：

- client_00：目标客户端，因子为 \(A_t,B_t\)。
- client_01：正常参照客户端，因子为 \(A_1,B_1\)。
- client_02 至 client_09：八个正常背景客户端，因子为 \(A_j,B_j\)。

所有公式按 LoRA 模块分别计算。

客户端权重：

\[
p=0.1
\]

八个正常背景客户端的加权贡献：

\[
A_{bg}=p\sum_{j=2}^{9}A_j
\]

\[
B_{bg}=p\sum_{j=2}^{9}B_j
\]

U 的真实聚合因子：

\[
A_U=A_{bg}+pA_t+pA_1
\]

\[
B_U=B_{bg}+pB_t+pB_1
\]

### 4.2 计算目标和正常参照的因子变化

定义：

\[
D_A=p[(A_t-A_g)+(A_1-A_g)]
\]

\[
D_B=p[(B_t-B_g)+(B_1-B_g)]
\]

其中，目标客户端和正常参照客户端必须来自同一轮、同一个全局检查点。禁止跨轮组合上传。

### 4.3 构造 A、B 两个客户端

独立设置：

\[
\lambda_A,\lambda_B\in(0,10)
\]

客户端 A：

\[
\boxed{
\begin{aligned}
A_a&=A_g+\lambda_A D_A\\
B_a&=B_g+(10-\lambda_B)D_B
\end{aligned}
}
\]

客户端 B：

\[
\boxed{
\begin{aligned}
A_b&=A_g+(10-\lambda_A)D_A\\
B_b&=B_g+\lambda_BD_B
\end{aligned}
}
\]

### 4.4 联合恢复证明

A、B 和八个背景客户端执行因子 FedAvg：

\[
\begin{aligned}
A_{AB}
&=pA_a+pA_b+A_{bg}\\
&=p(2A_g+10D_A)+A_{bg}\\
&=2pA_g+D_A+A_{bg}\\
&=pA_t+pA_1+A_{bg}\\
&=A_U
\end{aligned}
\]

同理：

\[
B_{AB}=B_U
\]

因此：

\[
\boxed{A_{AB}=A_U,\qquad B_{AB}=B_U}
\]

LoRA 有效权重：

\[
W=W_0+sBA,\qquad s=\frac{\alpha}{r}=2
\]

所以：

\[
\boxed{W_{AB}=W_U}
\]

联合恢复关系对任意合法的 \(\lambda_A,\lambda_B\) 均成立。参数选择只影响 A、B 单独上传时的有效更新和因子变化，不影响联合恢复的代数结果。

### 4.5 单客户端有效更新展开

客户端 A 的有效更新：

\[
\begin{aligned}
\Delta W_a/s
&=B_aA_a-B_gA_g\\
&=\lambda_A B_gD_A\\
&\quad +(10-\lambda_B)D_BA_g\\
&\quad +\lambda_A(10-\lambda_B)D_BD_A
\end{aligned}
\]

客户端 B 的有效更新：

\[
\begin{aligned}
\Delta W_b/s
&=B_bA_b-B_gA_g\\
&=(10-\lambda_A)B_gD_A\\
&\quad+\lambda_BD_BA_g\\
&\quad+\lambda_B(10-\lambda_A)D_BD_A
\end{aligned}
\]

上述交叉乘积项必须保留。不得只根据 \(\lambda_A,\lambda_B\) 的数值或 A/B 因子拼接范数判断单客户端影响。

### 4.6 数学实现要求

1. 使用当前全局因子作为 A、B 两个客户端的共同基线。
2. 不执行 Procrustes 旋转。
3. 不从目标因子中扣除背景因子。
4. A、B 因子分别执行服务器真实 FedAvg。
5. 不把因子变化范数当作有效权重更新范数。
6. 所有数学验收使用 float64。
7. 所有输入模块、张量形状、数据类型和有限性必须严格检查。
8. 不允许通过容差放宽、跳过模块或替换输入掩盖误差。

## 5. 有效更新与参数筛选

### 5.1 三类独立尺度

对任意客户端 X，计算：

有效更新范数：

\[
N_X=
\sqrt{
\sum_m
\left\|
s(B_{X,m}A_{X,m}-B_{g,m}A_{g,m})
\right\|_F^2
}
\]

A 因子变化范数：

\[
F_{A,X}=
\sqrt{
\sum_m\|A_{X,m}-A_{g,m}\|_F^2
}
\]

B 因子变化范数：

\[
F_{B,X}=
\sqrt{
\sum_m\|B_{X,m}-B_{g,m}\|_F^2
}
\]

三个指标分别记录。禁止将 A、B 两个因子合并成一个指标后直接判定全部合格。

### 5.2 正常客户端参照

每轮使用 U 的九个正常客户端 client_01 至 client_09，分别计算：

- 有效更新范数中位数 \(M_N\)。
- A 因子变化范数中位数 \(M_{F_A}\)。
- B 因子变化范数中位数 \(M_{F_B}\)。

目标客户端和正常参照客户端的所有指标都必须来自同一轮、同一全局检查点。

### 5.3 225组参数筛选

固定15个候选值：

\[
\Lambda=
\{0.1,0.25,0.5,1,2,3,4,5,6,7,8,9,9.5,9.75,9.9\}
\]

完整遍历：

\[
(\lambda_A,\lambda_B)\in\Lambda\times\Lambda
\]

共225组参数。

对每组参数，在U的全部30轮真实上传上构造A、B，并计算：

\[
J=
\max_{r,X\in\{A,B\},q\in\{N,F_A,F_B\}}
\left|
\ln\frac{q_{X,r}}{M_{q,r}}
\right|
\]

合格条件：

\[
\boxed{J\le\ln 2}
\]

等价于三个尺度在所有轮次均处于对应正常客户端中位数的0.5至2倍范围。

如果某轮正常参照中位数为零或出现非有限数值，参数筛选阶段立即失败。如果某个候选的对应指标为零，该候选直接判定为不合格并记录原因。

候选排序：

1. J 从小到大。
2. J 相同时，选择距离 \((5,5)\) 更近的候选。
3. 仍然相同时，按 \(\lambda_A\)、\(\lambda_B\) 数值升序排列。

没有任何候选通过时，停止后续拆分训练。禁止扩大参数范围或放宽合格条件。

### 5.4 低秩迹公式验证

有效更新范数的正式实现可以使用低秩迹公式，避免完整生成稠密的 BA 矩阵。

但必须增加独立验证：

1. 直接从真实 U 上传读取多个 LoRA 模块，使用这些真实因子比较低秩迹公式和显式 BA 计算。
2. 对真实 U 的目标客户端、正常参照客户端和构造出的 A/B 客户端分别核验。
3. 比较单模块结果和跨模块平方和结果。
4. 检查交叉项的正负号和矩阵乘法顺序。
5. 使用真实 U 张量测试多组 lambda 和边界附近的合法取值。
6. 对所有候选参数检查结果有限性。

低秩迹公式与显式 BA 计算的 float64 相对误差不得超过 \(10^{-8}\)。

主要评分采用：

- 华宇缺陷的放行减暂缓 Margin。
- 城东和北港缺陷的放行减暂缓 Margin。
- 目标答案与相反答案的对数概率差。

二值放行率作为辅助指标。

Bootstrap 以商品 ID 为抽样单位，至少2000次。四个分支必须使用相同商品集合，保持配对关系。

## 8. S-A、S-B 多轮真实训练

### 8.1 S-A 每轮训练

每轮从 S-A 自己的当前全局检查点开始：

1. 训练目标参照客户端 T，使用3组题对和14条普通任务。
2. 训练正常 client_01。
3. 训练正常 client_02 至 client_09。
4. 使用 T 和 client_01 构造 A。
5. 实际上传 A、client_01 和八个背景客户端。
6. 十个客户端按0.1权重执行因子 FedAvg。

### 8.2 S-B 每轮训练

每轮从 S-B 自己的当前全局检查点开始：

1. 训练目标参照客户端 T，使用3组题对和14条普通任务。
2. 训练正常参照 client_01，保存为 shadow reference。
3. 训练正常 client_00。
4. 训练正常 client_02 至 client_09。
5. 使用 T 和 shadow reference 构造 B。
6. 实际上传正常 client_00、B 和八个背景客户端。
7. shadow reference 只用于 B 的数学构造，不进入实际上传、聚合、检测或客户端数量统计。
8. 十个实际上传客户端按0.1权重执行因子 FedAvg。

### 8.3 多轮训练检查点

S-A、S-B 各训练30轮，使用同一个正式选定的 \(\lambda_A,\lambda_B\)。

每轮保存：

- 当前全局检查点。
- 十个实际客户端上传。
- 目标参照 T。
- 正常 shadow reference（仅 S-B）。
- A/B 构造输入和输出。
- 每个客户端的数据 sample_id。
- 训练损失和耗时。
- 因子范数和有效更新范数。
- Norm、Cosine、FoolsGold 原始分数。
- 固定探针评价。
- round manifest 和文件 SHA256。

断点恢复必须核对模型、配置、数据、优化器设置、上传文件和上一轮全局检查点。所有检查通过后，从下一轮继续。

### 8.4 自动阶段验收

r5：检查数值稳定性和客户端更新尺度。

r15：检查模型行为是否出现严重退化。

r25、r30：执行完整1152条开发集评价。

硬停止条件：

- 任意张量出现 NaN 或 Inf。
- 客户端上传模块缺失或形状错误。
- 客户端有效更新范数超过同轮正常客户端中位数的4倍，或低于0.25倍。
- 全局 A/B 因子拼接范数连续两轮超过 U 对应轮次的4倍。
- 全局有效 BA 权重范数超过 U 对应轮次的3倍。
- 正常商品准确率连续两轮低于90%。
- 检查点哈希与轮次清单不一致。

r15 如果正常商品准确率低于90%，或华宇、城东、北港三个仓库的缺陷放行率均达到90%，立即停止该分支。

r25 和 r30 的正式行为要求：

- 华宇缺陷放行率 ≤10%。
- 城东缺陷误放率 ≤10%。
- 北港缺陷误放率 ≤10%。
- 正常商品准确率 ≥95%。
- 三个仓库的缺陷 Margin 均小于0。
- 闭集准确率相对 N 下降不超过5个百分点。

S-A、S-B 必须分别通过。任何一个分支失败，都如实保留另一个分支的结果，不得将失败分支标记为完成。

## 9. S-AB 联合构造与检测

S-AB 不建立独立多轮训练轨迹。

每一轮直接使用 U 的真实十客户端上传：

1. 从 U client_00 和 client_01 计算 D_A、D_B。
2. 按正式选定参数构造 A、B。
3. 保留 U 的 client_02 至 client_09 八个背景上传。
4. 组成 A、B 和八个背景客户端的十客户端集合。
5. 执行真实服务器 FedAvg 复算。
6. 与 U 同轮聚合检查点逐模块比较。

每轮验收：

\[
\max |A_{AB}-A_U|\le10^{-6}
\]

\[
\max |B_{AB}-B_U|\le10^{-6}
\]

\[
\frac{\|W_{AB}-W_U\|_F}{\max(\|W_U\|_F,10^{-12})}
\le10^{-5}
\]

另外，在固定探针和完整开发集上比较逐提示对数概率、Margin 和生成分类。数学相同的模型必须得到相同推理结果。

S-AB 检测输入必须从 A、B 实际构造上传重新计算。禁止复制 U 的检测分数。

## 10. 检测器与聚合防御

### 10.1 检测器输入

| 方法 | 输入 |
|---|---|
| Norm | 完整有效更新 \(s(B_iA_i-B_gA_g)\) 的范数 |
| Cosine | 完整有效更新之间的原始余弦相似度 |
| Cosine anomaly score | 1减去平均客户端余弦相似度 |
| FoolsGold | 当前客户端相对全局模型的 A/B 因子变化，结合历史记录 |
| CBDF | 最后一层七个 LoRA 模块的有效更新关系 |

Cosine 原始相似度必须限制在[-1,1]。原始余弦值和异常分数使用不同字段名。

S-B 的 shadow reference 不进入任何检测器输入。

### 10.2 阈值校准

复用经过完整审计的正常 N 轨迹：

- N_dolly_s42_a5：校准。
- N_dolly_s2026_a5：校准。
- N_dolly_s17_a5：独立误报检验。

Norm、Cosine、FoolsGold 使用正常客户端分数确定5%目标误报工作点。阈值只在校准数据上确定，正式结果不得重新调节阈值。

CBDF 使用固定的算法参数和边连接规则，并同时报告正常轨迹上的误报情况。

如果 N 轨迹的配置、数据、检查点或检测记录审计失败，检测评价阶段停止。不得用 U、S-A、S-B 或 S-AB 的结果反向校准阈值。

### 10.3 检测指标

逐轮和完整轨迹分别报告：

- TP、FP、TN、FN。
- Accuracy。
- Precision。
- Recall。
- F1。
- FPR。
- ROC-AUC。
- PR-AUC。
- 客户端异常分数和排名。
- 每轮恶意客户端是否被识别。
- S-AB 的 A、B 是否被分别识别。
- CBDF 是否识别出客户端组合。

所有指标必须同时提供实际样本数量和分母。30轮结果存在时间相关性，统计区间采用按轮次分组的重采样方法，不得把30轮直接当作30个独立随机种子。

### 10.4 Multi-Krum 与 Trimmed Mean

固定 Multi-Krum：

\[
n=10,\quad f=2,\quad selected=8
\]

满足：

\[
n>2f+2
\]

报告每轮客户端入选名单、排除名单，以及 A/B 的入选和排除频率。

固定 Trimmed Mean 每个参数位置裁剪两端各两个客户端的值，保留中间六个值。

两种方法均执行离线聚合回放，不反馈给正式训练过程。回放后重新加载模型，评价1152条开发集，记录仓库行为和正常商品准确率变化。

Multi-Krum 的客户端排除记录与 Norm、Cosine 等检测器的指标分开报告。Trimmed Mean 只报告聚合结果和行为变化。
