# FedLoRA-Guard 实验结果与迭代方案

2026 年 11 月 13 日 · 评审修订与良性基准 · 历史批次 `abc_20261113_135849`

## 1 研究目标

研究联邦 LoRA 训练中，客户端更新如何在多轮聚合中累积成全局模型危害，以及服务器能否在聚合前识别实际高危的更新或群体。服务器可读取收到的模型、各客户端上传、历史记录和公开探针，客户端私有训练样本及实验干预真值只用于离线验证。

当前要检验的命题是 **在预先规定的训练窗口内，每个目标客户端从第 1 轮起单独持续参与时，造成的行为影响都小。多个客户端从第 1 轮起共同持续参与时，联合影响超过实用阈值。** 该命题目前缺少完整轨迹中的单人成分测量。历史 G4 仅验证了六轮设置下的群体行为危害。若要主张超加性，需预先规定响应尺度，并检验联合效应是否超过各成员单独效应之和。如果要主张四名成员缺一不可，需要评价全部真子集。聚合前检测属于另一项命题，需要用独立保留轨迹检验可观察分数能否预测实测危害。防御收益需要通过独立运行的过滤轨迹测量。

原有 ABC 的分工仍适用。A 量化客户端和群体影响，提供离线评价依据。B 检验历史信息能否带来额外识别能力。C 检验客户端关系与公开行为证据能否提高高危群体的检出率。检测到投毒身份、观察到超加性、拦截后降低危害，分别需要不同证据。 [当前 ABC 设计快照][abc-design]

## 3 完整训练轨迹的配对实验

### 3.1 轨迹与数据身份

令 $G$ 为预先登记的四名目标成员。对每个独立轨迹家族，执行一条 clean、四条单成员以及一条四成员轨迹。各轨迹从相同初始化开始，后续每一轮使用自己上一轮产生的全局状态。四名成员在各自单独分支与联合分支中的实验处理定义固定，避免把分支间的处理变化混入比较。

家族内共用数据分区、样本归属、训练调度、优化步数和评价清单。用同一份带稳定 `sample_id` 的原始数据清单校验所有分支。实验输入采用已登记的基准视图及其对应正常视图，保存两者的来源与哈希。跨家族使用独立的数据划分、成员分配和训练随机性。评价提示与训练数据隔离，禁止按保留集输出反向挑选数据。

六条轨迹足以检验四名成员各自弱、四人共同强。若研究问题还包括最小高危集合与各阶交互，每个家族需要全部 16 条轨迹，包括六条两成员和四条三成员轨迹。历史六轮数据用于复现旧实验，后续确认性分析使用独立家族。逐轮分别记录实际曝光、唯一源记录数和重复次数。单人和四人在固定成员处理下累计曝光不同，因此联合效应包含剂量变化。客户端分布的独立效应需要单独的剂量匹配对照。

| 对照 | 固定条件 | 解释 |
| --- | --- | --- |
| 固定成员处理 | 单人和联合分支中，同一成员的处理定义与样本日程固定 | 检验该处理和六轮窗口内是否单人弱、联合强 |
| 同剂量分配 | 使用已有、预先登记且可匹配的基准输入，匹配逐轮实际曝光、唯一源记录数、重复次数及总优化步。等权 FedAvg 保持参与者及每个客户端的权重固定，分别报告受控成员权重总和 | 估计在可比剂量下，集中和分布条件的结果差异。差异仍可能包括客户端归属和本地更新路径的变化 |

历史配置中单客户端每轮只消费 20 条记录，原 G4 每轮有 80 次曝光，无法用同配置补出 80 次曝光的单人匹配分支。剂量对照限定在预先登记的共同可行范围，实际曝光不符的配对记录为不匹配。已有基准存在多个剂量点时，报告各剂量的响应曲线。只在共同支持范围内比较，剂量曲线的形状无法单独识别客户端间机制。若没有符合条件的基准，报告固定成员处理的结果，并将独立分布效应记为未识别。

### 3.2 统计判定

对家族内同一轮定义 $D_t(S)=Y_t(S)-Y_t(\varnothing)$。$Y_t$ 的危害阈值的主端点为 ASR。交互的主端点为逐提示教师强制目标 logp，使用每监督 token 均值及固定 EOS 口径。ASR 概率和预登记裁剪规则下的 logit 作为交互敏感性分析。触发与无触发对照、正常任务效用均报告。六轮协议逐轮评价，正式登记单人弱影响的等效界值 $\epsilon$、联合危害界值 $\tau$ 与联合强的连续轮次。以第 5、6 轮作为连续联合窗口是设计建议，执行前需要冻结。

| 命题 | 判定依据 |
| --- | --- |
| 全程单人弱 | 四条单成员轨迹在所有登记轮次的效应区间均落在 $[-\epsilon,\epsilon]$。区间过宽记为证据不足 |
| 多人持续参与后强 | 四成员轨迹在预定连续轮次上的效应下界均超过 $\tau$ |
| 超加性 | $E_t(G)=D_t(G)-\sum_{i\in G}D_t(\{i\})$。目标 logp 尺度上的区间下界大于零才支持正超额效应。第 5、6 轮均值作为确认性对比，逐轮结果同时报告 |
| 最小高危集合 | 该集合的联合效应下界超过 $\tau$，全部真子集的效应上界低于 $\tau$ |

“单人弱、多人强”与超加性可以分别成立。四人各增加 3 个百分点，联合增加 12 个百分点，在危害阈值为 10 个百分点时，联合分支越过阈值，超额效应仍为 0。任何尺度上的可加性都依赖所选端点。固定成员处理下的正交互可以来自剂量响应曲线或跨轮动力学，需要剂量对照和机制消融才能进一步归因。高阶分解采用子集差分，$E_t(G)$ 等于六项二阶、四项三阶及一项四阶交互之和。

同一家族内以相同提示配对。正式推断以独立训练家族为单位，保留每个家族的逐轮原始差。单人弱与联合强作为预登记的联合判定，确认性报告采用按家族构造的同时区间。若开展最小集合搜索，对登记的全部非空子集构造同时区间，再对满足阈值的集合检查全部真子集。真子集上界低于 $\tau$ 是单侧危害上界判定；单人效应落入双侧等效界值才属于等效检验。

用三个独立家族的六条轨迹估计方差及首次越过 ASR 阈值的时点差异。这些家族只用于方差和运行成本估计。$\epsilon$ 和 $\tau$ 在查看试点结果前根据危害口径登记。以保守方差范围和目标区间宽度确定确认样本量，家族数很少时给出敏感性分析。辅助端点为首次达到预登记 ASR 阈值的轮次，例如 50%。训练窗口内未达到的轨迹按右删失记录。样本量充分时，可用家族随机效应和分支与轮次交互描述 logp 曲线。六轮内单人弱的结论只覆盖该训练窗口、剂量和协议。 [等效检验方法][equivalence] · [全因子设计][factorial]

## 4 良性联邦客户端互补实验

在实验服务器的项目环境中，从仓库根目录执行：

```bash
python -m src.benign.complementarity \
  --output artifacts/abc/benign_complementarity/results.json
```

使用项目已有的 PyTorch、NumPy 和 SciPy，在 CPU 上运行。默认每个种子训练四条完整轨迹，每条轨迹有十个客户端、六轮训练。每名客户端从本轮全局参数开始，在自己的正常数据上执行十次完整批次梯度更新，再将参数交给项目的等权 FedAvg 聚合。训练数据是程序按固定种子生成的带正负信号的正常二分类样本。模型按任务读取对应的输入分量。

| 分支 | 客户端 0 的本地任务 | 客户端 1 的本地任务 |
| --- | --- | --- |
| `00` | 背景任务 | 背景任务 |
| `10` | 子任务 A | 背景任务 |
| `01` | 背景任务 | 子任务 B |
| `11` | 子任务 A | 子任务 B |

各分支共享初始参数、参与客户端、训练步数及每个客户端的记录数量。其余客户端始终训练背景任务。四分支的区别来自服务器收到的客户端训练更新。所有分支在同一组固定的配对样本上评价。子任务仅在预测正确且预测置信度达到 `--confidence-threshold` 时通过，联合题要求同一对样本的 A 和 B 都通过。

对两个评价端点分别计算 `10−00`、`01−00`、`11−00` 和交互项 `11−10−01+00`。主端点为两项同时通过的比例，辅助端点为两项通过率的平均值。

| 检查 | 默认判定或读法 |
| --- | --- |
| 单独影响弱 | 联合端点的两个单独增量均在 ±5 个百分点以内 |
| 联合影响强 | 联合端点的联合增量超过 25 个百分点 |
| 超加性 | 联合端点的交互项大于零 |
| 定位交互来源 | 对照两种端点。若正交互出现在两项同时通过的比例上，而单项均值的交互接近零，观察到的超加性可由联合通过条件解释 |
| 核对客户端贡献 | 检查逐客户端参数差，确认 A、B 的更新来自对应的本地训练，并核对背景任务通过率 |
| 核对聚合后的参数交互 | 用 `parameter_interaction_by_task` 查看每个权重分量的四分支差分。若 A、B 权重的交互接近零而联合通过率的交互为正，参数结果与可加的子任务学习相容 |

默认在三个训练种子的第 5、6 轮分别判定。只有每个指定种子的每个指定轮次都满足单独和联合界值，批次才报告满足该命题。可通过 `--help` 查看种子、训练轮次、置信度和判定阈值参数。JSON 保存实际配置、逐客户端更新、全局参数、逐对命中及两个端点的全部对比。

该任务刻意设置两个分别可学的子任务，用于观察联邦本地训练产生的行为互补，并检查联合评价的定义如何影响交互。结论限于固定评价样本及训练配置。训练家族的方向一致性属于描述性检查。这个 CPU 入口使用独立的小型模型，项目中的 Qwen/LoRA 聚合机制需要另外利用实际权重和检查点评价。

### 4.1 单一任务上的联邦 LoRA 交叉项实验

在服务器的项目环境中从仓库根目录运行：

```bash
python -m src.benign.lora_cross_term \
  --output artifacts/abc/benign_lora_cross_term/results.json
```

这是一个单任务矩阵补全实验。两名客户端都最小化同一个平方误差目标，只看到同一目标矩阵的不同观测位置。两名客户端从相同的 rank-1 LoRA 适配器开始，各自计算真实梯度并执行一次本地微调。基座权重冻结，服务器使用仓库的等权 FedAvg 分别聚合 LoRA 因子。四个分支共享初始权重、客户端数、训练步数和留出评价位置。对照客户端训练初始模型已能拟合的锚点，因此对应的更新为零。

设初始因子为 $A_0=[0,1]$、$B_0=[0,1]^\top$，目标矩阵所有元素为 1。第一个客户端观察第二行第一列，仅更新 $A$。第二个客户端观察第一行第二列，仅更新 $B$。评价始终只看客户端训练时都没有见过的左上角。每个本地模型在其可见观测上可以改善，但单独上传时，留出位置的有效权重仍为零。共同聚合时，两份更新通过 $\overline B\overline A$ 的乘积影响同一个留出位置。

| 分支 | 参与聚合的训练更新 | 留出位置预测的解析参照 |
| --- | --- | ---: |
| `00` | 两份锚点训练更新 | 0 |
| `10` | 仅第一名客户端的观测更新 | 0 |
| `01` | 仅第二名客户端的观测更新 | 0 |
| `11` | 两名客户端的观测更新 | 0.25 |

脚本计算 $C=W_{11}-W_{10}-W_{01}+W_{00}$，并核对它是否等于 $\Delta B_2\Delta A_1/4$。随后在相同留出位置评价 $W_{11}-C$，并评价直接平均两份客户端的有效权重。两项对照的解析预测均为零。联合分支的解析平方误差为 $(1-0.25)^2=0.5625$，相对基线减少 0.4375。如果实测符合解析参照，联合改善可归因于本轮因子聚合后的乘积交叉项。输出同时保存本地训练损失、各分支留出误差、因子更新、权重差分和检查结果。

该实验从明确给出的非零 LoRA 检查点开始，用 CPU 上的小型线性层验证一次聚合的机制。效应定义在同一个留出目标上。表中的数值是解析参照，Qwen/LoRA 上的强度和可重复性需要用独立数据及检查点评价。

## 5 拆分器与机制验证

### 5.1 同轮 LoRA 权重消融

历史第 6 轮回放验证的单位是固定训练起点下的一次聚合。加载实际上传和同起点的正常替代上传，按原参与顺序和权重重建 `neither / a / b / ab`，逐分支核对适配器摘要及生成结果。设各分支实际有效更新为 $W_{ij}=s B_{ij}A_{ij}$，其中 $s$ 为 LoRA 缩放系数。对每个模块计算

$$
C=W_{11}-W_{10}-W_{01}+W_{00},
\qquad W_{\mathrm{add}}=W_{11}-C.
$$

固定权重的因子平均下，设 $\delta A_i,\delta B_i$ 为实际上传与正常替代上传的因子差，则

$$
C=s p_a p_b(\delta B_a\delta A_b+\delta B_b\delta A_a).
$$

对任意子集 $S$，在同一收到的全局模型和固定权重下，权重关于成员指示变量是二次多项式：

$$
C(S)=s\sum_{i<j\in S}p_i p_j(\delta B_i\delta A_j+\delta B_j\delta A_i),
\qquad
W_{\mathrm{add}}(S)=W(S)-C(S).
$$

三阶及以上的权重子集差分恒为零。三阶及以上行为交互仍可能由网络响应或独立训练轨迹产生。精确线性聚合有效更新 $sB_iA_i$ 时，在固定上传和固定权重的当轮替换实验中，跨客户端权重交叉项为零。这个结论限于当轮聚合，跨轮状态与行为仍可能发生交互。

先在归档第 6 轮读取真实张量，报告每模块 $\lVert C\rVert_F$、$\lVert W_{11}-W_{00}\rVert_F$、两者之比，以及全模块平方范数之和开方后的比值。分母接近零时保留绝对范数并把比值记为未定义。范数只用于确定消融工程投入。即使范数很小，特定方向仍可能影响模型输出。安排一个 $ab$ 的配对消融后，再依据行为区间和研究问题决定是否计算全部子集。

使用 FP64 聚合因子核对解析式，使用实际加载的因子构造消融。将四分支有效更新的带符号低秩和用于推理修正，保留完整修正精度，避免截断回原秩。逐模块记录重建误差，校验零修正及撤除修正都能复现 `ab`。配对输出原模型与消融模型的 ASR、逐提示目标 logp 和正常任务指标。

对完整 G4 的某一轮，若要拆分每一阶行为交互，需要评价 16 个真实子集以及 11 个额外可加分支。空集和四个单成员分支共用记录。对真实和可加分支分别计算子集交互，两者之差表示该阶行为交互对移除权重交叉项的响应。只比较完整群体的实际分支与可加分支，则得到交叉项对该群体总危害的即时影响。三个成员以上，这两个量通常不同。

### 5.2 跨轮历史与当前轮效应

从四成员和 clean 轨迹各取同一登记轮次的上一轮状态，记为 $P$ 和 $N$。将上一轮状态与当轮处理组成两个因素，得到 $Z(P,G)$、$Z(P,\varnothing)$、$Z(N,G)$、$Z(N,\varnothing)$。主轨迹提供第一项和最后一项，其余两项需要从各自指定的全局状态执行真实当轮训练。保留相同参与、样本调度和优化步数。

| 对比 | 解释 |
| --- | --- |
| $Z(P,\varnothing)-Z(N,\varnothing)$ | 先前状态在当前轮正常训练后仍保留的影响 |
| $Z(N,G)-Z(N,\varnothing)$ | 从正常历史出发的当轮影响 |
| $Z(P,G)-Z(P,\varnothing)-Z(N,G)+Z(N,\varnothing)$ | 前一轮状态与当轮处理的交互 |

三项相加得到该轮四成员轨迹与 clean 的总差。这个历史交互来自两种训练起点的对照，同轮 $C$ 则来自固定起点的聚合权重干预。两者分别记录。

## 7 Dolly 与 PKU 良性跨数据集验证

### 7.1 训练与评价

Dolly 使用既有摘要与信息抽取分支。PKU 使用服务器上的正常视图 `data/processed/pku_smoke_len256_200/clean_records.jsonl`、同目录的清单及固定版本的 PKU 原始文件。以原始配对元数据中的 Privacy Violation 和 Economic Crime 作为主题分类依据，排除同时属于两类的记录。训练和评价只使用安全回答，生成的记录移除 `unsafe_response` 字段内容。两个主题用于检验安全应答学习的互补性，主题归类不等同于评估模型安全性。

### 7.2 检测器的跨数据集误报

使用原参考轨迹拟合监督分类器，并用原校准轨迹确定阈值。在单次回放中对所有新良性分支应用相同模型和阈值，保留原始逐客户端得分。报告全体客户端误报、两个专业化客户端各自误报、以及每轮这两名客户端至少一人被告警的频数。良性分支的召回率和 AUROC 记为未定义。测试分支可以复用随机种子，参考与测试仍按运行路径、家族名称及训练数据摘要隔离。共享数据来源与可能的记录重叠限制跨域泛化的解释。CBDF 保留原生阈值，其余方法使用参考校准阈值。
