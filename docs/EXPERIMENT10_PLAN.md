## 统计判据

同一种子内为四条轨迹使用相同提示。先逐提示配对，再按种子和模板族处理相关性。设 $Y_{ab}$ 为目标正例正确率，$E_A=Y_{10}-Y_{00}$，$E_B=Y_{01}-Y_{00}$，$E_{AB}=Y_{11}-Y_{00}$，$I=Y_{11}-Y_{10}-Y_{01}+Y_{00}$。

| 判据 | 确认性要求 |
| --- | --- |
| 单独效应 | $E_A$、$E_B$ 的两个 90% 区间分别完整落入 ±5 个百分点。 |
| 联合收益 | $E_{AB}$ 的 95% 区间下界超过 15 个百分点。 |
| 超加性 | $I$ 的 95% 区间下界大于零。 |
| 辅助指标 | 每分支报告困难负例误报率、普通任务正确率和标签连续评分。分开解释参数机制、分类结果与检测结果。 |

功效模拟中使用 $I=E_{AB}-E_A-E_B$。设 $E_A=E_B=0$ 且 $E_{AB}=0.20$ 时，联合情景中的 $I$ 为 0.20。原设计的 $I=0.05$ 可用于交互单项敏感性分析。报告区分单项功效和四项同时通过的概率。现有审计入口要求至少两个种子和每类至少两个模板族，这属于输入格式下限，正式样本数量由独立功效分析确定。

## 本地 agent 执行验收

1. 开始前保存 Git 提交、模型和 tokenizer 版本、配置、种子、数据与模板族清单、划分摘要、生成评分规则及每客户端每轮训练预算。先测量实际微批次和生成吞吐量，再估算服务器用时。
2. 复用现有 FedAvg、训练器与检查点机制。在同一已登记条件下验证正常训练和中断恢复。各阶段留下命令、退出状态、持续时间和可核验日志。
3. 将 JSONL 中的评价记录关联到种子、分支、轮次、模板族、样本、提示摘要、检查点摘要及适配器摘要。另行保存每轮聚合权重、客户端上传与冻结检测分数。
4. 批次报告包含生效配置、逐提示 JSONL、检测器校准记录、汇总 JSON 和 `RESULTS.md`。缺失阶段标为待实施、未运行或未验证。工程冒烟指标与确认性统计结果分别记录。
